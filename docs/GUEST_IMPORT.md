# CSV guest import

Open **Import guests from CSV** in the guest directory. Download the static template, upload a UTF-8 CSV and select default events. Review errors and duplicate-looking rows, edit row fields/events, revalidate, select valid rows and explicitly confirm each saved batch. Imported guests start Pending with zero attending people; no invitations or provider jobs are sent. Contacts/names are advisory duplicate hints, never merge keys.

`POST /api/v1/weddings/{weddingId}/guests/import-preview` accepts multipart `file` plus JSON `defaultInvitedEventIds`, or JSON `{rows,defaultInvitedEventIds,previousPreviewToken?}`. File size is at most 1,000,000 bytes; multipart envelopes are bounded to 1,015,000 bytes and data rows to 1,000. JSON bodies retain the existing 256 KiB limit. Headers are required `name` and optional `email`, `phone`, `max_party_size`, `notes`; unknown/duplicate headers, invalid UTF-8 and malformed quoting are rejected. BOM, CRLF/LF, quoted commas/newlines and escaped quotes are accepted. Empty optional text becomes null, empty party size becomes one. Events are chosen in the UI, not encoded in CSV cells.

Preview resolves verified Admin/Manager access and admits bounded work before parsing CSV. It creates no guests. Each source row has a stable 1-based number, values, field errors, advisory warnings and an imported/changed flag. Valid rows are bound by a signed, 30-minute manifest containing wedding/actor/request identity and SHA-256 normalized row digests, with no contacts or names in the token. HMAC signing uses a separate purpose under the existing wedding encryption key. Files and row buffers are temporary; no import file/session collection is stored.

JSON revalidation verifies the prior token's actor/wedding/signature even after expiry, retains the server UUID and re-signs edited row digests. Bounded subset revalidation retains the previously signed digests for untouched source rows; the UI merges refreshed subsets and checkpoints each token so large previews fit JSON limits. Invalid edited rows lose their digest. Changes to previously valid rows are reported; already-imported rows are labelled and never treated as updates.

`POST .../guests/import` accepts `{importRequestId,previewToken,rows}` with at most 200 exact reviewed rows. Duplicate source numbers or changed contents are rejected before the transaction. Live membership, token expiry, deployment party cap and active wedding-scoped event assignments are rechecked under the wedding fence. The transaction bulk-reads source markers, validates all missing rows and bulk-inserts them atomically, returning `created` or `already_imported` and guest IDs. Replay returns existing IDs without overwriting edits, even after the originally assigned events become unavailable. A separate import UUID creates separate records.

Source fields `importRequestId`/`importRowNumber` are optional together on guests. The partial unique `uq_guest_import_row` index enforces `(weddingId, importRequestId, importRowNumber)` identity; it is initialized when guest storage is used. New collection validation checks both source fields are present together. Existing collection validators are not changed through live `collMod`; service validation and the unique index enforce the import contract. Ordinary guest projections exclude source markers and bearer material. Guest deletion remains deferred; if a source record is deliberately deleted later, an explicit recommit can recreate it. The UI does not automatically recommit completed rows.

Preview and commit share atomic fixed-window budgets of 20 attempts/minute per account/wedding and 60 per wedding, using hashed identifiers in existing rate-limit storage. Exhaustion returns 429 with Retry-After. No new credential or dependency is needed. `409 IMPORT_PREVIEW_EXPIRED` requires refresh retaining the same UUID; `422 IMPORT_PREVIEW_CHANGED` requires revalidation. Origin/custom-header checks apply to both JSON and multipart.

The UI saves one explicit batch per click, bounded by row count and encoded body bytes. A lost response locks that exact source batch against editing and allows only explicit idempotent retry or signed refresh; acknowledged rows are never automatically replayed. Directory data is explicitly reloaded, with dashboard totals refreshed from saved records. Refreshing the browser loses this temporary review; keep an uncertain preview open for recovery rather than uploading the same file as a new import.

Run `npm run check:guests:import`, `npm run check:guests:import:browser`, `npm run check:guests`, `npm run check:contracts`, lint, typecheck and build. Checks use disposable replica sets and synthetic browser fixtures without Atlas/provider writes; browser tooling follows `docs/GUESTS.md`.
